# Устройство FINOMALY

## Эпизод и данные

Эпизод задаёт одну виртуальную компанию и один отчётный период. Сначала генератор создаёт согласованные счета, платежи и журнал двойной записи. Каждая группа проводок имеет общий идентификатор транзакции. Затем генератор меняет учётное событие и запоминает причину, затронутые ID, размер расхождения и допустимые доказательства. Ошибка может оставить книги сбалансированными по дебету и кредиту, как при двойном проведении одной сбалансированной записи.

Четыре типа изменений покрывают повторное начисление, оставшуюся в расчётах сумму оплаты, неверный пересчёт валюты и неверный период. Сочетания применяют два независимых изменения к одной операции. В чистых эпизодах и контрольных записях встречаются законные частичные платежи, возвраты и одинаковые суммы разных счетов. Деньги хранятся в целых минимальных единицах, курсы — в десятичных строках. Политика возвращается вместе с манифестом и описывает выбор курса и границы периода.

Генерация использует локальный PRNG и версию схемы. Те же параметры и seed дают ту же выгрузку. `episodes/catalog.json` содержит только открытые конфигурации. Обычный экспорт включает `manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv`, `policy.json`. Локально оценщик может явно сформировать `private/truth.json` и `private/provenance.json` через параметр `include_private=True`.

## Контракт и видимость

`reset(seed, config)` возвращает пару `(observation, info)`. `step(action)` принимает JSON-совместимый объект и возвращает `(observation, reward, terminated, truncated, info)`. Доступны `list_records`, `get_record`, `get_document`, `calculator` и `submit`. Страница содержит до 50 записей. Калькулятор разбирает только ограниченные десятичные выражения. Ошибочный запрос расходует шаг. Стотый шаг может быть отправкой выводов. Исчерпание бюджета или времени завершает проверку с пустым итоговым ответом.

В закрытой оценке политика получает только JSON-запросы и наблюдения через интерфейс среды. При сравнении скриптовых политик открытые адаптеры запускаются отдельным процессом с каналом stdin/stdout. Это разделение данных для штатных политик, операционные ограничения для стороннего кода задаёт запускающий стенд. Оценщик держит эталон и диагностику в своём процессе. Oracle используется оценщиком напрямую. Промежуточная награда всегда нулевая, а терминальная передаётся политике только в режиме обучения.

HTTP-слой предназначен для доверенного локального просмотра. Он показывает человеку открытые документы без расхода шагов, а встроенная скриптовая политика получает их через действия среды. Конфигурация закрытого прогона, seed и оценка закрытого эпизода не проходят через HTTP-слой. Для браузера используется отдельный тайм-аут 15 минут, чтобы можно было остановиться на шаге во время показа. Автономная среда по умолчанию использует лимит 60 секунд.

## Оценивание

Подтверждение учитывает тип, канонический набор затронутых ID, сумму, валюту и полный допустимый набор ссылок на доказательства. Идентификаторы чувствительны к регистру. Обычный допуск суммы — ноль минимальных единиц. Эталон может явно задать иной целочисленный допуск. Детерминированное сопоставление максимизирует число однозначных пар. У каждого вывода и каждого эталонного случая не больше одной пары. Повторный и неподтверждённый вывод учитываются как FP. Пропуск учитывается как FN.

Возврат равен `clip(2 * F1 - 1 - 0.002 * inspection_steps, -1, 1)`. При пустом эталоне и пустой отправке F1 равен 1. Ошибка схемы отправки завершает эпизод с наградой −1. Нейтральный текст обоснования не меняет оценку. Исследовательские действия входят в стоимость, а `submit` только расходует последний шаг бюджета.

Сверка строит выводы по публичным счетам, проводкам, платежам и курсам. На открытом наборе она служит воспроизводимой базовой политикой и в браузере, и в CLI. Случайный просмотр без правил часто заканчивается пустым отчётом, а массовые обвинения дают ложные срабатывания. Сравнение приведено в `BENCHMARK.md`. Оценка организаторов проводится на их закрытых материалах.

## Границы работы

Веб-сервер хранит 64 последних использованных сеанса в памяти одного процесса. Перезапуск завершает сеансы, а по достижении лимита удаляется самый давно использованный. API поддерживает встроенную политику и ручные JSON-действия. Интерфейс переключает темп встроенной политики, приостанавливает её и выполняет по одному действию. Открытые эпизоды и CLI предназначены для демонстрации. Бухгалтерские документы, лица, операции и курсы вымышлены.
