# FINOMALY · Гайд по фронтенду и подключению Python

В режиме API путь одного прогона выглядит так:

```text
Dashboard → auditClient → Python: генератор + reset
Audit Workspace → auditClient → Python: политика агента + step
Results ← итоговый снимок ← Python: оценщик
```

## 1. Как устроен фронтенд

| Файл | За что отвечает |
| --- | --- |
| `src/main.tsx` | Монтирует React-приложение и подключает стили |
| `src/App.tsx` | Dashboard, форма настроек эпизода, навигация между экранами |
| `src/useAuditRun.ts` | Текущий эпизод, ожидание запроса, ручной шаг, автопрогон, пауза и скорость |
| `src/auditClient.ts` | Выбирает демо или HTTP API, отправляет запросы и проверяет структуру ответов |
| `src/auditTypes.ts` | Общие типы и справочники сценариев и валют, форматирование сумм |
| `src/mockAudit.ts` | Локальный генератор синтетических записей и демо-прогоны, воспроизводимые с одинаковыми настройками и seed |
| `src/AuditScreens.tsx` | Таблицы, журнал агента, управление воспроизведением, метрики и выводы |
| `src/RecordInspector.tsx` | Подробности документа или проводки и переходы к связанным записям |
| `src/EvidenceChain.tsx` | Связи счёт → проводки → платежи на экране Results |
| `src/Visuals.tsx` и `src/App.css` | Иконки, общие карточки, тема и адаптивная раскладка |

При переходе на Python меняется источник, с которым работает `auditClient.ts`. Компоненты принимают один и тот же типизированный снимок эпизода в обоих режимах.

## 2. Что подключает бэкендер

| Часть | Обязанность Python |
| --- | --- |
| Генератор | По `seed`, сценарию, периоду и базовой валюте создаёт записи, документы и закрытый эталон |
| Среда | Инициализирует состояние через `reset(seed, config)`, выполняет действия через `step(action)`, ведёт бюджет |
| Политика агента | Выбирает следующее действие и формирует выводы с ID доказательств |
| Оценщик | Сопоставляет выводы с эталоном и выдаёт разрешённые итоговые метрики |
| HTTP-слой | Создаёт эпизод, сохраняет состояние по `id`, выполняет один шаг на запрос и собирает открытый снимок для интерфейса |

Фронтенд передаёт конфигурацию, вызывает шаги по одному и отображает снимок. Пауза отменяет запланированные клиентом шаги. Уже отправленный запрос может завершиться. Для официальной проверки Python-ядро запускается своим автономным способом.

## 3. Настройка подключения

В каталоге `finomaly-frontend` скопируйте `.env.example` в `.env.local` и укажите действующий префикс Python API:

```env
VITE_AUDIT_API_URL=http://127.0.0.1:8000/api
```

Запустите Python-сервер и перезапустите Vite командой `npm run dev`. Пустое значение включает локальные данные. При настроенном URL ошибки API видны в интерфейсе, а автопрогон останавливается. Переменная читается при запуске или сборке Vite. Используйте её только для адреса API.

Если браузер и API работают на разных портах, разрешите фактический origin фронтенда на Python-сервере, например `http://127.0.0.1:5173`, и поддержите CORS preflight для JSON POST. Альтернатива — прокси с тем же origin.

## 4. Первый запрос — создать эпизод

`POST /episodes` относительно префикса API. Данные запроса передаются в snake_case:

```json
{
  "company_name": "Demo Company",
  "scenario": "allocation_fx",
  "error_types": ["partial_allocation", "fx_rate"],
  "seed": 42,
  "base_currency": "JPY",
  "period_start": "2026-10-01",
  "period_end": "2026-10-31"
}
```

Валидируйте целочисленный `seed` от 0 до 4 294 967 295, включительные границы периода в формате `YYYY-MM-DD`, код валюты и соответствие `scenario` списку `error_types`. Генератор использует именно параметры запроса. Для одинаковой конфигурации и версии среды генерация должна быть воспроизводимой.

| `scenario` | `error_types` |
| --- | --- |
| `duplicate_invoice` | `["duplicate_invoice"]` |
| `partial_allocation` | `["partial_allocation"]` |
| `fx_rate` | `["fx_rate"]` |
| `period_cutoff` | `["period_cutoff"]` |
| `allocation_fx` | `["partial_allocation", "fx_rate"]` · обе ошибки относятся к одному платежу |
| `duplicate_cutoff` | `["duplicate_invoice", "period_cutoff"]` · обе ошибки относятся к одному начислению |
| `clean` | `[]` |

Базовые валюты в интерфейсе — `KZT`, `USD`, `EUR`, `GBP`, `CHF`, `CNY`, `JPY`, `UZS`. Поддержите эти коды в генераторе и его справочнике курсов. Документ платежа может содержать отдельную валюту. Передавайте её в поле `currency` самого документа.

Суммы в API — целые числа в минимальных единицах конкретной валюты. `amountMinor: 12345` означает 123,45 USD для `USD` и 12 345 иен для `JPY`. При обмене Python переводит сумму в основные единицы исходной валюты, применяет курс и округляет результат в минимальных единицах валюты назначения. Курсы локального демо заданы для тестов.

## 5. Снимок, который возвращает API

Оба метода возвращают полный JSON-снимок. Ключи ответа передаются в camelCase. Пример ответа после создания эпизода:

```json
{
  "id": "FIN-42",
  "status": "running",
  "stepBudget": 100,
  "stepsRemaining": 100,
  "ledger": [
    {
      "id": "L-104",
      "date": "2026-10-03",
      "description": "Начисление по счёту",
      "amountMinor": 187500,
      "currency": "JPY",
      "counterparty": "Orion Services",
      "invoiceId": "INV-019",
      "documentIds": ["DOC-I019"]
    }
  ],
  "documents": [
    {
      "id": "DOC-I019",
      "date": "2026-10-03",
      "reference": "INV-019",
      "kind": "Счёт",
      "amountMinor": 187500,
      "currency": "JPY",
      "counterparty": "Orion Services",
      "invoiceId": "INV-019"
    }
  ],
  "trace": [],
  "result": null
}
```

Связи в боковой панели и цепочке доказательств строятся по `id`, `invoiceId` и `documentIds`. Сохраняйте ID стабильными в пределах эпизода. `ledger`, `documents` и `trace` приходят массивами, в том числе пустыми. Для `documents[].kind` текущий адаптер принимает `Счёт`, `Платёж` и `Курс FX`. Поле `note` у документа можно опустить.

## 6. Второй запрос — выполнить шаг

`POST /episodes/{id}/step`. Фронтенд отправляет `{"expected_step": 1}` для первого шага. Python выбирает действие, выполняет его в среде и возвращает обновлённый снимок. В `trace` добавляется запись:

```json
{
  "number": 1,
  "action": "get_document",
  "params": {"doc_id": "DOC-I019"},
  "records": [{"source": "documents", "id": "DOC-I019"}],
  "spentSteps": 1,
  "stepsRemaining": 99,
  "status": "ok",
  "observation": "Открыт первичный счёт DOC-I019."
}
```

- `number` начинается с 1. В каждом ответе `trace` содержит историю с начала эпизода.
- `records[].source` принимает `ledger` или `documents`. ID указывает на открытый объект в соответствующем массиве снимка.
- `expected_step` служит защитой от повторного расхода бюджета. Если этот шаг уже выполнен, верните снимок с ним. При одновременных запросах проверяйте номер вместе с сохранением шага.
- Статус эпизода — `running`, `completed` или `truncated`. Статус шага — `ok`, `error`, `terminated` или `truncated`. Действие с ошибкой может быть частью журнала даже при успешном HTTP-ответе.
- Во время прогона `result` равен `null`. Для завершённого прогона оценщик может передать `precision`, `recall`, `f1`, `reward` и `findings`. При `truncated` список выводов пуст, а `result` может быть `null`.

Один объект `findings` содержит `id`, `type`, `title`, `explanation`, `amountMinor`, `currency`, `affectedIds` и `evidenceIds`. Тип берётся из четырёх типов ошибок. `affectedIds` выделяет спорные записи, `evidenceIds` ссылается на документы и операции, подтверждающие вывод. Точные определения находятся в [auditTypes.ts](src/auditTypes.ts).

Передавайте в браузер только разрешённые записи, параметры действий и наблюдения. Закрытый эталон, результаты закрытого оценивания и seed закрытых эпизодов храните на стороне Python.

## 7. В каком порядке интегрировать

1. Подключить создание эпизода. Проверить в Network, что выбор JPY или другой новой валюты меняет `base_currency`, а Python возвращает записи в требуемых валютах.
2. Подключить один ручной шаг. Проверить, что в журнале появился запрос, а бюджет обновился по ответу сервера.
3. Повторить отправку с тем же `expected_step`. Убедиться, что второй запрос возвращает тот же шаг и бюджет расходуется один раз.
4. Проверить завершённый и усечённый прогоны. Убедиться, что видны разрешённые метрики и что ID в выводах открывают соответствующие записи.
5. Запустить автопрогон. Проверить паузу, восстановление после сетевой ошибки и повторяемость данных с одним `seed`.
