# Как пользоваться FINOMALY

FINOMALY показывает, как агент проверяет синтетические финансовые данные. Вы задаёте условия проверки, наблюдаете за запросами агента и разбираете выводы по документам. Одна такая проверка называется **эпизодом**.

## 1. Dashboard — настроить проверку

На Dashboard вы отвечаете на вопрос «Что проверяем?». Для быстрого показа нажмите **«Запустить демо»**. Симулятор возьмёт текущие настройки, откроет рабочую область и начнёт выполнять действия. Кнопка **«Запустить аудит»** под формой открывает эпизод на первом шаге и оставляет управление вам.

| Настройка | Зачем нужна |
| --- | --- |
| **Название компании** | Помогает отличать прогоны и показывает, чьи записи открыты в рабочей области. |
| **Сценарий** | Задаёт, какое расхождение заложено в синтетические данные. Чистый сценарий показывает, как агент работает с согласованными записями. |
| **Seed** | Число для воспроизведения набора данных. Повторите запуск с теми же настройками и seed, чтобы сравнить поведение на одинаковых записях. |
| **Базовая валюта** | Валюта учёта компании. Первичный документ может быть в другой валюте. Такой случай виден, например, в сценарии с валютным курсом. |
| **Начало и конец периода** | Границы проверки. В сценарии с ошибкой периода сравните дату первичного документа и дату проводки с этими границами. |

Четыре отдельных сценария проверяют повторное начисление, неполное распределение платежа, неверный курс и запись за пределами периода. В двух комбинированных сценариях ошибки связаны с одним платежом или начислением. Для первого знакомства подойдёт «Дублирование счетов».

После нажатия **«Запустить аудит»** откроется Audit Workspace. Карточка **«Текущий прогон»** на Dashboard показывает статус и позволяет вернуться к активному аудиту или открыть его итог.

## 2. Audit Workspace — увидеть, как агент проверяет данные

Это рабочая область одного эпизода. Здесь можно сверить, **что агент запросил, что среда ему вернула и как это связано с выводом**.

- **Проводки** показывают операции в учёте компании. **Документы** показывают первичные источники, например счёт или подтверждение платежа. Нажмите ID записи, чтобы открыть дату, сумму, валюту, контрагента и связанные записи.
- **История действий** показывает запросы по порядку. Раскройте шаг, чтобы увидеть параметры, ответ, полученные записи и расход бюджета. Например, `get_document` с `doc_id: DOC-I019` означает, что агент запросил этот счёт.
- **«Следующее действие»** выполняет один шаг. Так удобнее разбирать, что изменилось после отдельного запроса.
- **«Запустить всё»** выполняет оставшиеся шаги последовательно. **«Скорость»** задаёт паузу между ними. **«Пауза»** останавливает следующие запросы, а текущий может успеть завершиться.

### Зачем нужен бюджет в 100 шагов

**100 шагов — максимальное число действий агента на один эпизод, включая итоговую отправку выводов.** Это ограничение кейса Genesis. Оно задаёт одинаковый лимит для прогонов и позволяет увидеть, сколько запросов понадобилось агенту для проверки.

Пример с базовым демо:

| Остаток | Что произошло |
| --- | --- |
| **100 / 100** | Эпизод открыт, агент ещё не выполнил ни одного действия. |
| **99 / 100** | Агент запросил список проводок. На это ушёл один шаг. |
| **97 / 100** | Агент выполнил три запроса и собрал данные для вывода. |
| **96 / 100** | Агент отправил вывод и завершил эпизод. |

Открытие карточки документа, переключение вкладки и раскрытие журнала оставляют бюджет прежним. Это действия пользователя в интерфейсе. Бюджет меняется при выполнении действия агентом.

Статус **«Завершён»** означает штатное завершение прогона. **«Исчерпан лимит»** означает остановку по лимиту шагов или времени. В этом состоянии итоговые выводы могут быть недоступны.

## 3. Results — проверить выводы и доказательства

Откройте Results после завершения прогона. Сначала прочитайте вывод, затем нажмите ID в **«Цепочке доказательств»**, чтобы сверить его с исходными записями.

В сценарии дублирования счёт `DOC-I019` связан с проводками `L-104` и `L-136`. Обе отражают одно начисление по тому же счёту на одинаковую сумму. Цепочка также показывает платежи по счёту. Метка **«Затронута»** выделяет проводки, на которые указывает именно этот вывод.

| Метрика | Как читать |
| --- | --- |
| **Точность (Precision)** | Какая доля выводов агента подтвердилась. Если подтверждены 3 из 4 выводов, точность равна 0,75. |
| **Полнота (Recall)** | Какую долю заложенных ошибок агент нашёл. Если найдены 3 из 5, полнота равна 0,60. |
| **F1** | Одна оценка, учитывающая и точность, и полноту. При точности 0,75 и полноте 0,60 она составляет около 0,67. |
| **Награда** | Итог по правилам кейса. Качество выводов повышает награду, а количество действий расследования немного её снижает. |

Для чистого эпизода пустой ответ считается правильным. В правилах кейса для этого случая F1 равен 1, а точность и полнота — 0, поскольку делить не на что. В режиме **«Локальное демо»** метрики и записи демонстрационные. В режиме API метрики приходят от оценщика.

## Быстрый показ на демо

В Results кнопка **«Скачать отчёт»** сохраняет один HTML-файл с настройками, метриками, выводами и журналом. Получатель может открыть его в браузере без сети. Нажатие на ID доказательства переносит к строке исходной записи. Для бумажной версии или PDF подойдёт обычная команда печати браузера.

В локальном демо можно обновить страницу прямо во время проверки. При доступном хранилище браузера та же вкладка восстановит экран и последнее завершённое действие. Автоматическое воспроизведение продолжится после нажатия **«Запустить всё»**.

1. На **Dashboard** выберите «Дублирование счетов» и нажмите «Запустить аудит».
2. В **Audit Workspace** нажмите «Следующее действие». Раскройте первый шаг истории и покажите, что осталось 99 из 100 шагов.
3. Переключитесь на «Документы» и откройте `DOC-I019`. Покажите связанные проводки `L-104` и `L-136`.
4. Нажмите «Запустить всё», затем «Открыть результаты». Покажите, какие записи связывают вывод с исходным счётом.
