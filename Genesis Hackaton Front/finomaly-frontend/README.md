# FINOMALY · Фронтенд

React, TypeScript, Vite и CSS. По умолчанию приложение запускает локальное демо с синтетическими данными. Официальная проверка Genesis Hackathon запускает Python-среду отдельно.

## Запуск

В папке проекта выполните:

```powershell
npm install
npm run dev
```

Сборка и проверка типов — `npm run build`.

## Демонстрация

1. Выберите один из семи сценариев и задайте `seed`, базовую валюту и границы периода.
2. В Audit Workspace нажмите ID документа или проводки. Подробности показывают исходную валюту, контрагента и связанные записи.
3. Раскройте шаг в истории, чтобы увидеть параметры запроса, наблюдение, расход бюджета и полученные записи.
4. Запускайте действия вручную или кнопкой «Запустить всё». Скорость управляет интервалом между запросами. «Пауза» останавливает будущие шаги, а уже отправленный запрос может завершиться.
5. На Results откройте узел цепочки доказательств. Метка «Затронута» относится к конкретному выводу.

В локальном демо сценарий и конфигурация изменяют синтетические записи. Метрики демонстрационные. Для повтора задайте ту же конфигурацию и тот же seed.

## Предлагаемый контракт Python API

Укажите префикс API в `.env.local` и перезапустите Vite:

```env
VITE_AUDIT_API_URL=http://127.0.0.1:8000/api
```

Пустое значение выбирает локальное демо. Настроенный API обслуживает все запуски и шаги. Ошибки сервера отображаются в интерфейсе, автопрогон приостанавливается.

### Создание эпизода

`POST /episodes` относительно `VITE_AUDIT_API_URL`. Python использует параметры при вызове генератора и сбросе среды.

```json
{
  "company_name": "Demo Company",
  "scenario": "allocation_fx",
  "error_types": ["partial_allocation", "fx_rate"],
  "seed": 42,
  "base_currency": "KZT",
  "period_start": "2026-10-01",
  "period_end": "2026-10-31"
}
```

Идентификаторы четырёх типов — `duplicate_invoice`, `partial_allocation`, `fx_rate`, `period_cutoff`. Комбинации `allocation_fx` и `duplicate_cutoff` применяют обе ошибки к одному платежу или начислению. Сценарий `clean` передаёт пустой `error_types`.

### Действие агента

`POST /episodes/{id}/step` с телом `{"expected_step": 1}` для первого действия. Номер начинается с 1. Сервер выполняет следующее действие той же политики. Если запрос с тем же номером уже был обработан, сервер возвращает сохранённый снапшот или текущий снапшот с этим шагом. Вместе с последовательной отправкой на клиенте это предотвращает повторный расход бюджета при сетевом сбое.

### Ответ обоих методов

Тело — JSON-объект снапшота. Обязательные верхнеуровневые поля:

| Поле | Значение |
| --- | --- |
| `id` | Строковый ID эпизода, стабильный на протяжении прогона |
| `status` | `running`, `completed` или `truncated`. Последние два соответствуют завершению и усечению среды |
| `stepBudget`, `stepsRemaining` | Полный и оставшийся бюджет, целые числа |
| `ledger`, `documents` | Массивы открытых записей и документов. Связи проводок с документами передаются в `documentIds` |
| `trace` | Журнал с начала эпизода по текущий шаг, включая `params`, полученные `records`, `spentSteps`, `stepsRemaining`, `status` и `observation` |
| `result` | `null` во время прогона. После завершения — разрешённые оценщиком метрики и выводы или `null`, если итог недоступен. При `truncated` список выводов пуст |

Точные поля вложенных объектов зафиксированы в `src/auditTypes.ts`. Входные параметры HTTP-запроса передаются в snake_case, а поля снапшота — в camelCase, как в типах. Денежные значения — целые числа в минимальных единицах указанной валюты. Используйте ISO-коды валют и стабильные ID для открытых записей.

Python-слой формирует ответы из разрешённых полей. Закрытый эталон, seed закрытых эпизодов и данные оценщика до завершения остаются на сервере. Для разных локальных портов разрешите origin Vite на стороне API через CORS или используйте прокси с тем же origin.
